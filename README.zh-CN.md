# 动量因子复现与交易成本敏感性研究

一项可复现的实证研究，复刻 Jegadeesh & Titman (1993) 美股普通股价格动量异象，并在此基础上扩展参数稳健性检验与交易成本敏感性分析。数据灌入、信号构建、组合形成、统计推断的全流程用 MySQL 8 与 R 实现，由 `targets` 编排管线，并通过 `testthat` 自动化数据完整性与前视偏差检验。

[English README](README.md)

## 1. 研究问题

Jegadeesh & Titman (1993) 提出的 12 个月建仓、跳过 1 个月（"12-1"）动量策略，在现代美股全市场样本上是否仍能产生异常收益？该结论对建仓窗口与跳过期参数的选择有多敏感？在扣除现实交易成本后，异常收益能剩下多少？

## 2. 数据

| 数据序列 | 来源 | 覆盖范围 | 备注 |
|---|---|---|---|
| 个股月度收益 | WRDS/CRSP，Stock-Version 2（CIZ 新版格式，2024-11-22 迁移）→ Monthly Stock File | 1990-01 至 2025-12 | 全库检索；股票范围通过 `securitytype='EQTY' AND securitysubtype='COM'` 限定为普通股（详见 §3.1） |
| Fama-French 因子 | WRDS → Fama-French Portfolios → 5 Factors Plus Momentum（月度） | 1990-01 至 2025-12（共 432 个月） | WRDS 导出的数值为小数形式，非 Ken French 官网公开数据那种百分比乘以 100 的单位 |

最终灌入样本规模：**2,667,625** 条个股月度观测，覆盖 **23,700** 只不同证券（`permno`）。

WRDS 数据受再分发限制，不提交进本仓库（`data/` 已加入 `.gitignore`）。

### 2.1 CIZ 数据迁移与股票范围过滤

CRSP 于 2024 年 11 月完成从旧版"SIZ"格式到新版"CIZ"格式的迁移，取消了历史上用来限定普通股范围的 `shrcd`（股票代码）字段（旧版做法为 `shrcd IN (10, 11)`）。取而代之，CIZ 提供 `securitytype` 与 `securitysubtype` 两个字段。**WRDS 官方文档并未以易于查到的形式说明这一映射关系**，本项目通过对已知证券做实测查询、交叉核对返回字段的方式，自行确定了取值对应关系：

| 代码 | 类型 | `securitytype` | `securitysubtype` | `sharetype` |
|---|---|---|---|---|
| AAPL, MSFT, IBM | 普通股 | `EQTY` | `COM` | `NS` |
| SPY, VNQ | ETF | `FUND` | `ETF` | `NS` |

区分逻辑完全落在 `securitytype` 这一层（`EQTY` 对 `FUND`），`securitysubtype` 提供二次确认；`sharetype` 在两类证券间取值相同，未参与筛选。灌数时实际应用的过滤条件为 `securitytype = 'EQTY' AND securitysubtype = 'COM'`。

### 2.2 重复记录

CIZ 官方文档提示，若单只证券在同一月内发生多笔分配事件，可能产生重复的 `(permno, mth)` 观测。本项目实测确认了这一现象（例如 `permno=10001` 在 `1994-06-30` 出现两条数值完全相同的记录）。重复记录通过 `GROUP BY permno, mth` 配合 `MAX(ret)` 折叠去重，前提假设是重复行的收益值本身相同——这一假设已对观测到的样例做过验证，但尚未对全部 267 万行数据做穷举式核实（对应的验证查询已写在 `sql/02_load_wrds.sql` 中）。

## 3. 研究方法

### 3.1 信号构建

对每一组参数（建仓窗口 *N*、跳过期 *S*），第 *t* 月的动量信号定义为过去 *N* 个月的累计复利收益，且跳过最近 *S* 个月：

```sql
signal_t = EXP( SUM( LN(1 + ret) ) OVER (
             PARTITION BY permno ORDER BY mth
             ROWS BETWEEN (N+S-1) PRECEDING AND S PRECEDING
           ) ) - 1
```

由 MySQL 窗口帧边界的语义可知，只要 *S* ≥ 1，当前行（第 *t* 月本身）在任何情况下都不会被纳入信号计算，这一构造方式从设计上就杜绝了前视偏差。本研究计算了四组 (formation, skip) 参数配置：(3,1)、(6,1)、(12,1)、(12,3)，分别标记为 `F3_S1`、`F6_S1`、`F12_S1`、`F12_S3`。

这一构造的正确性并非仅停留在设计层面的声明，而是由 `R/tests/test-lookahead-bias.R` 独立验证：该测试从数据库中随机抽样信号记录，在 R 层用原始收益序列独立重新计算信号值，并核对两者在 1e-6 容差范围内数值相等。

### 3.2 组合构建与重叠持仓期

沿用 Jegadeesh & Titman (1993) 的做法，每月按信号值将股票分入五个分位（`NTILE(5)`，quintile 1 为跌幅最大的"输家"，quintile 5 为涨幅最大的"赢家"），每期持有 *K* = *N* 个月（持有期长度等于建仓窗口长度），且每月都会形成一批新的建仓组合。这一设计产生重叠持仓期结构：在任一给定的日历月，实际组合收益是过去 *N* 个建仓月份所形成批次的混合结果。

这一重叠结构通过一张显式的中间表 `holding_batches(formation_mth, hold_mth, permno, quintile, param_window, ret)` 实现，将每个建仓批次展开为其贡献持仓权重的每一个月份对应一行。月度组合收益随后计算为**当月所有活跃个股观测的单层等权平均**——也就是说，无论某只股票来自哪个建仓批次，都获得同等权重。

> **关于此前一处实现缺陷的说明。** 本聚合逻辑的早期版本先在每个建仓批次内部计算平均收益，再对各批次的批次均值取平均——这种两层平均隐含地给了每个"建仓批次"同等权重，而不是给每只"股票"同等权重。由于活跃批次的规模在稳态月份存在约13%的波动（例如在 `F12_S1`、quintile 1、`2000-06-30` 这一时点观测到 9 个活跃批次，规模从 1,243 只到 1,409 只股票不等），这种做法引入了可量化的聚合偏差。该问题在代码审查阶段被发现并实测确认，随后修正为上文所述的单层平均。第 5 节报告的结果反映的是修正后的计算方式；修正前后数字的差异幅度很小（第四位小数级别），但修正后的写法在方法论上才是正确的规范做法。

赢家减输家的价差组合（quintile 5 − quintile 1）以 `quintile = 6` 的形式存入 `port_returns` 表。

### 3.3 退市与幸存者偏差

在旧版 CRSP 数据格式下，退市收益（`dlret`）需要手动与常规收益合并，以避免幸存者偏差。而在 CIZ 新版格式下，`mthret` 字段本身已经并入了退市月的收益，因此不再需要单独的合并步骤。这是相对于旧版管线设计的一项结构性改进，但并不能消除 CRSP 数据整体固有的样本选择性问题（见第 6 节）。

### 3.4 统计推断

赢家减输家组合的收益对 Fama-French 三因子（Mkt-RF、SMB、HML）做回归。标准误采用 Newey-West (1987) 异方差与自相关一致估计量（`sandwich::NeweyWest`），滞后阶数按常见经验法则 ⌊4·(T/100)^(2/9)⌋ 选取，而非直接使用普通 OLS 标准误——考虑到持仓期构造本身会给收益序列引入强烈的重叠性与自相关性，这是本研究刻意强调学术严谨性的关键一环。

### 3.5 换手率与交易成本敏感性

换手率基于 `holding_batches` 表中实际的持仓成分（而非建仓时刻原始的分位排名）计算，定义为某分位在给定月份的成员中，上月未持仓于同一分位的比例。给定单边交易成本 *c*，净 alpha 建模为：

```
net_alpha(c) = gross_alpha - avg_turnover × c × 2
```

在 *c* ∈ [0, 50] 基点区间内以 1 基点为步长评估，并通过线性插值确定 breakeven 成本（净 alpha 首次归零的成本水平）。

### 3.6 设计原则：组合构建全部落在 SQL 层

所有分位排序、持仓期展开、收益聚合、换手率计算均在 SQL 层完成（`sql/` 目录）。R 层（`R/fns/`）对组合层面的数值严格只读——只负责回归、风险指标计算与绘图，绝不重新计算或推导任何组合收益数字。

## 5. 结果

样本区间：1990-01 至 2025-12，2,667,625 条个股月度观测，覆盖 23,700 只不同证券。赢家减输家（quintile 5 − 1）组合对 Fama-French 三因子回归结果：

| 参数窗口（建仓-跳过） | 月度 α | Newey-West t 值 | Newey-West p 值 | 年化夏普比率 | 最大回撤 | 交易成本 Breakeven |
|---|---|---|---|---|---|---|
| F3_S1（3-1） | 0.21% | 0.93 | 0.352 | −0.03 | 55% | 0 基点（即便无成本也已亏损） |
| **F6_S1（6-1）** | **0.62%** | **2.60** | **0.010** | **0.22** | 58% | 在测试的整个 0-50 基点区间内净 alpha 始终为正 |
| F12_S1（12-1，JT1993 标准设定） | −0.19% | −0.72 | 0.469 | −0.27 | 87% | 0 基点 |
| F12_S3（12-3） | −0.32% | −1.23 | 0.221 | −0.33 | 91% | 0 基点 |

**核心发现。** Jegadeesh & Titman (1993) 经典的 12-1 建仓-跳过参数设定，在这份 1990-2025 年美股全市场样本上**未能复现**：赢家减输家组合的 alpha 为负、统计上不显著，且伴随超过 85% 的最大回撤。唯一在统计上显著（Newey-West 标准误下达到 1% 显著性水平）、且在经济意义上对交易成本足够稳健的参数配置，是较短的**6 个月建仓、跳过 1 个月**窗口。

一项补充诊断分析（按持仓期内的月份序号拆解组合收益）显示，动量效应集中出现在建仓后的头一到两个月——这几个月内赢家组合确实跑赢输家组合——但随后在 12 个月持仓期的剩余时间里迅速衰减，甚至频繁反转。持仓窗口越长，就会把越大比例的衰减/反转期平均进最终收益，这足以完全抵消 12 个月窗口设定下早期积累的正 alpha。这一现象被作为一项实质性研究发现予以报告，而非数据或实现层面的瑕疵；它与文献中已有充分记录的"动量崩溃"（momentum crash）与衰减动态高度一致，不过按子区间或市场环境做正式拆解，留作后续工作（见第 6 节）。

## 6. 局限与未来工作

- **未做流动性或市值筛选。** 本轮研究未排除极小盘股，而这类股票可能因流动性差、买卖价差大而呈现被放大的类动量模式。
- **未做 2008 年前后的子区间分析。** 文献中已充分记录的 2008 年前后"动量崩溃"现象，本轮未单独分析；结合第 5 节识别出的衰减模式，按子区间拆解或许能进一步厘清 12 个月参数设定的失效，是否集中在特定的历史时期。
- **幸存者偏差。** CIZ 的 `mthret` 已并入退市月收益，相对旧版管线设计缓解了幸存者偏差的主要来源，但 CRSP 整体样本构成层面更广泛的影响并未做进一步校正。
- **持仓期内衰减模式的进一步拆解。** 本研究记录了早期动量效应及其后续衰减，但未按行业、市场环境或其他条件变量做进一步细分。
- **Tableau 呈现。** 可选加分项；若后续补做，需注意 WRDS 数据不能通过 Tableau Public 公开发布，面向公众的版本需要替换为其他数据源或使用静态截图。

## 7. 结果复现方式

1. 准备一个 MySQL 8 实例，设置环境变量 `MOMENTUM_DB_HOST`、`MOMENTUM_DB_PORT`、`MOMENTUM_DB_NAME`、`MOMENTUM_DB_USER`、`MOMENTUM_DB_PASSWORD`。
2. 从 WRDS 导出数据（CRSP CIZ Monthly Stock File 全库检索；Fama-French 5 Factors Plus Momentum 月度数据），按 `sql/02_load_wrds.sql` 文件头部注释所述的列格式预处理后，分别存为 `data/crsp_monthly.csv` 和 `data/ff_factors.csv`。
3. 依次执行 SQL 管线（需要客户端 `--local-infile=1` 且服务端 `SET GLOBAL local_infile=1`）：
   ```bash
   mysql < sql/01_schema.sql
   mysql --local-infile=1 < sql/02_load_wrds.sql
   mysql < sql/03_signal.sql
   mysql < sql/04_portfolios.sql
   mysql < sql/05_turnover.sql
   ```
4. 运行 R 管线：
   ```r
   renv::restore()
   targets::tar_make()
   testthat::test_dir("R/tests")
   ```
   全部 15 项 `testthat` 用例在真实数据库上均已通过验证，包括一项独立重算的前视偏差检查，以及边界条件测试（历史长度不足的股票被正确排除；`holding_batches` 无重复计入）。
